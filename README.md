# نظام إدارة المستثمرين — CALL & RENT

تطبيق عربي بالكامل لإدارة علاقة الشركة بمستثمريها: تسجيل المستثمرين ورؤوس أموالهم،
احتساب الأرباح الشهرية ونسبها، وإصدار تقارير **شهرية / ربع سنوية / نصف سنوية / سنوية**
بصيغة PDF بتصميم فاخر يليق بأصحاب رؤوس الأموال.

مبني على الهوية الرسمية للشركة: **الكحلي `#182B56` + الأبيض**، والشعار الرسمي مدمج
داخل التطبيق ويظهر في الواجهة وفي ترويسة كل تقرير.

## النشر

**الرابط:** https://ibraheemkhillah-wq.github.io/Call-Rent/ — ثابت لا يتغيّر.

### `npm run deploy` — المسار الأساسي

```bash
npm run deploy
```

يبني محلياً ويدفع الناتج إلى فرع `gh-pages`، فتنشره GitHub خلال دقيقة عبر خط
النشر الخاص بها.

**لماذا لا عبر GitHub Actions:** طابور آلات Actions يتعطّل أحياناً ساعات، فتقف
الوظيفة `queued` بلا آلة ثم تُلغى قبل أن تبدأ أصلاً. الدفع المباشر إلى `gh-pages`
لا يمرّ بذلك الطابور إطلاقاً.

**إعداد لمرة واحدة:** من **Settings ← Pages ← Build and deployment ← Source**
اختر **Deploy from a branch**، ثم Branch: `gh-pages` و Folder: `/ (root)`.

السكربت في `scripts/deploy-pages.sh`: يبني بـ `VITE_BASE=/Call-Rent/`، يضيف
`.nojekyll`، ويستخدم شجرة عمل منفصلة فلا يمسّ فرعك الحالي ولا ملفاتك غير
المحفوظة، ويعيد محاولة الدفع أربع مرات عند تعثّر الشبكة.

> **التكلفة:** صفر ودائماً. GitHub Pages مجاني بلا حد للمستودعات العامة —
> بلا سقف زيارات ولا مدة تجربة ولا بطاقة بنكية. وهذا المستودع عام.

### Cloudflare Pages — بديل أسرع (اختياري)

خيار مجاني آخر إن أردنا نشراً أسرع لاحقاً: يبني وينشر تلقائياً عند كل دفعة على
`main` خلال **٣٠–٦٠ ثانية**. المستودع مهيّأ له مسبقاً.

**إعدادات المشروع في Cloudflare (لمرة واحدة):**

| الحقل | القيمة |
|---|---|
| Framework preset | `Vite` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Production branch | `main` |
| إصدار Node | يُقرأ من ملف `.node-version` (٢٢) |

**لا تضبط `VITE_BASE`.** التطبيق على Cloudflare يجلس على جذر النطاق، والقيمة
الافتراضية `/` هي الصحيحة. المتغيّر لازم فقط للاستضافة تحت مسار فرعي مثل
`.../Call-Rent/`.

### GitHub Pages — مسار احتياطي

`.github/workflows/deploy.yml` يبقى قائماً كبديل. يعمل على `main` فقط عمداً:
مجموعة التزامن `pages` واحدة لكل المستودع، فأي تشغيل من فرع آخر يحجزها ويترك
نشرة `main` واقفة في الطابور.

### نقل البيانات عند تغيير الرابط

بيانات المستثمرين محفوظة في متصفح الجهاز ومرتبطة **بالرابط** لا بالحساب، فلا
تنتقل وحدها إلى رابط جديد. عند أي تغيير للاستضافة:

1. على الرابط القديم: **الإعدادات ← تصدير نسخة احتياطية** (ملف JSON).
2. على الرابط الجديد: **الإعدادات ← استيراد نسخة احتياطية**.
3. احذف التطبيق المثبَّت القديم من الشاشة الرئيسية وثبّت الجديد.

هذه العملية لمرة واحدة فقط؛ وتنتهي الحاجة إليها نهائياً عند الانتقال لاحقاً إلى
قاعدة بيانات على خادم مع تسجيل دخول.

### تحديث التطبيق المثبَّت
التطبيق يخزّن ملفاته محلياً ليعمل دون إنترنت، ولذلك قد تبقى نسخة قديمة عالقة على الجهاز
بعد نشر تحديث — خاصةً على iOS. لذلك:

- يُفحص التحديث تلقائياً عند فتح التطبيق، وكل دقيقتين أثناء الاستخدام، وعند كل عودة إليه،
  ويُطبَّق فوراً.
- **الإعدادات ← نسخة التطبيق** يعرض تاريخ الإصدار الحالي، ومعه زر **«التحقق من التحديثات»**
  للفحص الفوري عند الشك.

### تثبيته كتطبيق على الجوال
التطبيق **PWA** كامل: أيقونة بشعار الشركة، يفتح بملء الشاشة بلا شريط متصفح،
ويعمل **دون إنترنت** (كل الملفات والخطوط مخزّنة محلياً).

- **آيفون:** افتح الرابط في **Safari** ← زر المشاركة ⬆️ ← **إضافة إلى الشاشة الرئيسية**
  (لا يعمل التثبيت من Chrome على iOS).
- **أندرويد:** افتح الرابط في Chrome ← القائمة ⋮ ← **تثبيت التطبيق**.

## التشغيل محلياً

```bash
npm install     # مرة واحدة
npm run dev     # التشغيل للتطوير  → http://localhost:5173
npm run build   # بناء نسخة الإنتاج → مجلد dist/
npm run preview # معاينة نسخة الإنتاج
```

التطبيق يعمل بالكامل في المتصفح، ولا يحتاج خادماً أو قاعدة بيانات.
مجلد `dist/` بعد البناء يمكن رفعه كما هو على أي استضافة ثابتة.

مسار النشر يُضبط بالمتغيّر `VITE_BASE`، ويبقى `/` افتراضياً — وهو الصحيح على
Cloudflare Pages وعلى أي نطاق خاص. لا يُضبط إلا للاستضافة تحت مسار فرعي
(سير عمل GitHub Pages يضبطه بقيمة `/Call-Rent/`).

## ما الذي يقوم به التطبيق

### ١. المستثمرون
- إضافة كل مستثمر على حدة مع بياناته الكاملة (الاسم، الهاتف، البريد، رقم الهوية،
  تاريخ الانضمام، ملاحظات الاتفاقية).
- تحديد **مبلغ الاستثمار الأولي** عند الإضافة.
- تسجيل **حركات رأس المال** لاحقاً: إيداعات إضافية أو سحوبات، كل واحدة بتاريخها.
- رأس المال في أي لحظة = مجموع الإيداعات − مجموع السحوبات حتى ذلك التاريخ.

### ٢. الأرباح الشهرية
- **صفحة «الأرباح الشهرية»**: جدول واحد لتسجيل ربح كل المستثمرين لشهر معيّن دفعة واحدة.
- **من صفحة المستثمر**: تسجيل ربح شهر منفرد مع ملاحظة وحالة صرف.
- النسبة المئوية تُحتسب تلقائياً أثناء الكتابة.
- تتبّع حالة كل ربح: **مصروف** أو **مستحق** (بضغطة واحدة على الشارة).
- أداة اختيارية: أدخل **مبلغ الربح الإجمالي** للشهر واضغط «وزّع تلقائياً» فيُقسَّم على
  المستثمرين بنسبة رأس مال كل واحد — ثم يمكنك تعديل أي رقم يدوياً قبل الحفظ.

### ٣. التقارير PDF
اختر المستثمر (أو **جميع المستثمرين** دفعة واحدة) + نوع الفترة + السنة، ثم **«معاينة»**
لعرض التقرير أو **«إرسال التقرير»** لإرساله ملف PDF.

**كل تقرير في صفحة A4 واحدة** مهما طالت الفترة، ويحتوي على:

| القسم | المحتوى |
|---|---|
| الترويسة | الشعار، نوع التقرير، اسم المستثمر، رقم التقرير، تاريخ الإصدار، العملة |
| شريط المستثمر | تاريخ الانضمام، الهوية، الهاتف، البريد، حالة الحساب — في سطر واحد |
| الأرقام الرئيسية | **كم استثمر** • **كم ربح بالدولار** • **نسبة العائد للفترة %** • **العائد السنوي المكافئ %** |
| رسم بياني | أعمدة الربح + خط النسبة المئوية لكل شهر مع قيمها مكتوبة، لآخر 12 شهراً |
| التفصيل الشهري | لكل شهر: رأس المال، الربح، النسبة الشهرية، حالة الصرف |
| حركات رأس المال | الإيداعات والسحوبات داخل الفترة + رأس المال بداية ونهاية |
| الملخص التراكمي | إجمالي المستثمر، إجمالي الأرباح، المصروف، المستحق، العائد التراكمي |
| التوقيع والختم | اسم الشركة والموقّع وصفته، ثم **صورة التوقيع أسفلها** فوق سطر الاعتماد، ختم بالشعار، خانة توقيع المستثمر |

#### المعاينة مطابقة للملف المُرسَل — بحكم البناء
المستند الحقيقي يُبنى خارج الشاشة (`.report-source`)، ثم **يُلتقط مرة واحدة** إلى
`canvas` لكل صفحة. من هذا الالتقاط نفسه تُشتقّ **صور المعاينة** و**ملف الـ PDF** معاً
(`renderDocCanvases` في `src/lib/pdf.ts`) — فما يظهر في المعاينة هو حرفياً ما يصل
للمستثمر، لا نسخة ثانية قد يرسمها المتصفح بشكل مختلف.

هذا ما حلّ مشكلة اختفاء الشعار والتوقيع والختم من المعاينة على Safari في الجوال بينما
كانت تظهر في الملف: لم يعد للمعاينة مسار رسم مستقل أصلاً.

زر **«معاينة»** يفتح الصورة بملء الشاشة، وضغط صورة المعاينة يفعل الشيء نفسه.

#### إرسال التقرير للمستثمر
زر **«إرسال التقرير»** يحوّل الالتقاط نفسه إلى ملف PDF ثم يفتح قائمة مشاركة نظام
التشغيل مباشرة (واتساب، بريد، أي تطبيق) — فيصل للمستثمر مطابقاً لما تراه. على الأجهزة
التي لا تدعم مشاركة الملفات يُنزَّل الملف بدلاً منها.

> ⚠️ **لا تستخدم «مشاركة ← طباعة» من المتصفح** لإرسال التقرير. نافذة الطباعة تضيف رابط
> الموقع وتاريخاً وأرقام صفحات في أطراف الورقة، وتفرض هوامش تقصّ أطراف التقرير وتقسّمه
> على عدة صفحات — ولا يمكن إلغاء ذلك من داخل التطبيق (خاصةً على iOS حيث لا يتيح Safari
> إيقاف الترويسة والتذييل).

#### لماذا يُولَّد الملف داخل التطبيق
التطبيق ينشئ الملف مباشرة عبر `src/lib/pdf.ts` بدل نافذة طباعة المتصفح، لأن
النافذة تضيف **رابط الموقع والتاريخ ورقم الصفحة** في أطراف الورقة وتفرض هوامش تقصّ
أطراف التقرير — ولا يمكن التحكم بذلك من CSS.

يُلتقط المستند بـ `html-to-image` تحديداً (عبر SVG foreignObject) لأن المتصفح نفسه هو
من يرسم النص، فيبقى **وصل الحروف العربية وتشكيلها سليماً**. المكتبات التي تعيد رسم
النص بنفسها — مثل `html2canvas` — تكسر وصل الحروف في العناوين ورؤوس الجداول.

#### كيف يبقى التقرير في صفحة واحدة
عند طول المحتوى (تقرير سنوي بـ 12 شهراً) لا يُقصّ ولا ينتقل لصفحة ثانية: يُكبَّر صندوق
الصفحة نفسه مع الحفاظ على نسبة A4 (المتغيّر `--page` في `.doc`)، فيتّسع المحتوى، ثم
يُصغَّر المستند كاملاً إلى 210×297مم عند التصدير. كل ذلك عبر التخطيط الطبيعي بلا
`transform` ولا `zoom`، فيخرج المستند مطابقاً على الشاشة وفي الـ PDF وفي الطباعة.

> عند اختيار «جميع المستثمرين» يخرج ملف واحد، **صفحة مستقلة لكل مستثمر**.
>
> زر «طباعة» يبقى متاحاً للطباعة الورقية المباشرة.

## قواعد الاحتساب

| المؤشر | المعادلة |
|---|---|
| رأس المال في نهاية شهر | مجموع الإيداعات − السحوبات حتى آخر يوم في الشهر |
| النسبة الشهرية | ربح الشهر ÷ رأس المال في نهاية ذلك الشهر × 100 |
| نسبة عائد الفترة | إجمالي أرباح الفترة ÷ **متوسط** رأس المال خلال أشهرها × 100 |
| العائد السنوي المكافئ | نسبة عائد الفترة × عدد الفترات المماثلة في السنة (شهري ×12، ربعي ×4، نصفي ×2) |
| العائد التراكمي | إجمالي الأرباح منذ البداية ÷ رأس المال القائم × 100 |

متوسط رأس المال يُحتسب على الأشهر التي كان فيها رأس مال فعلي فقط، حتى لا تنخفض النسبة
بسبب أشهر ما قبل انضمام المستثمر.

## الرؤية النهارية والليلية

زر التبديل (☀︎/☾) في أعلى الشريط الجانبي، والاختيار الكامل من **الإعدادات ← وضع العرض**:

| الخيار | السلوك |
|---|---|
| رؤية نهارية | خلفية فاتحة ونصوص كحلية |
| رؤية ليلية | الوضع الكحلي الداكن |
| حسب إعداد الجهاز | يتبع نظام التشغيل ويتغيّر معه فوراً (الافتراضي) |

الاختيار محفوظ بمفتاح مستقل (`call-rent-theme`)، فلا يدخل في النسخ الاحتياطية
ولا ينتقل مع البيانات عند الاستيراد.

> **التقارير المصدَّرة لا تتأثر بالوضع إطلاقاً** — تبقى دائماً على ورق أبيض بترويسة
> كحلية، لأنها مستندات للطباعة والإرسال. (مُتحقَّق منه: مخرجات التقرير متطابقة
> بكسل ببكسل في الوضعين.)

كل ألوان الواجهة معرّفة كرموز في `src/styles.css` تحت `:root[data-theme='dark']`
و`:root[data-theme='light']` — لتعديل أي لون في وضع معيّن، غيّر الرمز في كتلته فقط.

## الهوية البصرية

### الألوان
مستخرجة مباشرة من ملف الشعار الرسمي — الهوية لونان فقط:

| اللون | القيمة | الاستخدام |
|---|---|---|
| الكحلي الرسمي | `#182B56` | الخلفيات، الترويسات، رؤوس الجداول |
| الأبيض | `#FFFFFF` | النصوص والشعار فوق الكحلي |
| فضي/بلاتيني (مشتق) | `#C3CFE6` | الإبرازات والأزرار الأساسية |
| أزرق فولاذي (مشتق) | `#3E5C99` | الإبراز فوق الورق الأبيض في التقارير |

الفضي والفولاذي مشتقان من الأبيض والكحلي وليسا لوناً جديداً — الهوية الرسمية لا تحتوي
لوناً ثالثاً، فلم يُقحَم أي لون غريب عنها.

> الأخضر والكهرماني في شارات «مصروف / مستحق» ألوان **وظيفية** للحالة وليست جزءاً من
> الهوية، وهي العُرف المتّبع في الأنظمة المالية.

### الشعار
الشعار الرسمي مدمج في المشروع بنسختين شفافتين:

| الملف | الاستخدام |
|---|---|
| `src/assets/logo-light.png` | الشعار الأبيض — فوق الخلفيات الكحلية (الواجهة + ترويسة التقرير) |
| `src/assets/logo-dark.png` | الشعار الكحلي — فوق الخلفيات الفاتحة |
| `src/assets/logo-mark.png` | كتلة الاسم بلا السطر التعريفي — داخل ختم الاعتماد |
| `src/assets/signature.png` | التوقيع المدمج فوق سطر التوقيع في التقارير |

> صور الهوية والتوقيع **مضمَّنة في الحزمة كـ data URI** (عبر `assetsInlineLimit` في
> `vite.config.ts`) لا كروابط ملفات. السبب: توليد الـ PDF يلتقط الصفحة عبر SVG
> foreignObject، وأي صورة برابط خارجي تحتاج جلباً قد يفشل فتختفي من الملف الناتج.

**التوقيع واسم الموقّع** يُعدَّلان من **الإعدادات ← العملة والتوقيع**: اسم الموقّع،
صفته، وصورة توقيعه (مع إمكانية العودة للتوقيع المدمج).

يظهر تلقائياً على أي جهاز بدون أي رفع يدوي. ولو أردت شعاراً مختلفاً مؤقتاً، ارفعه من
**الإعدادات** فيتجاوز الشعار المدمج (ويمكن العودة إليه بزر «العودة للشعار الرسمي»).

### أين تُعدَّل
| ما تريد تغييره | الملف |
|---|---|
| ألوان وخطوط ونصوص الهوية (مرجع واحد) | `src/theme/brand.ts` |
| ألوان الواجهة | متغيّرات `:root` في `src/styles.css` |
| ألوان التقارير | متغيّرات `.doc` في `src/report.css` |
| اسم الشركة، السطر التعريفي، التواصل، العملة، التوقيع | صفحة **الإعدادات** داخل التطبيق |

المتغيّرات الأساسية: `--navy-900` … `--navy-500` (تدرّجات الكحلي، و`--navy-700` هو اللون
الرسمي `#182B56`)، و`--accent` / `--accent-light` / `--accent-dark` (الفضي).

الخطوط (IBM Plex Sans Arabic للنصوص + Amiri للعناوين والتقارير) مستضافة محلياً في
`src/assets/fonts/`، فتظهر التقارير بنفس الشكل حتى بدون إنترنت.

## البيانات والنسخ الاحتياطي

⚠️ البيانات محفوظة في **متصفح هذا الجهاز فقط** (localStorage). لا تُرسل إلى أي خادم.

هذا يعني:
- مسح بيانات المتصفح أو استخدام جهاز آخر = لن تجد بياناتك.
- **صدّر نسخة احتياطية بانتظام** من صفحة الإعدادات (ملف JSON)، واحتفظ بها في مكان آمن.
- لاستعادة البيانات أو نقلها لجهاز آخر: «استيراد نسخة احتياطية» من نفس الصفحة.
